## 金融解释

**衡量什么**：相邻两期收盘价的相对变动 $r = P_t / P_{t-1} - 1$，再做 signed-log 变换（保号、压缩尾部）。

**为什么有信息量**：收益率本身**不带方向**——同一个序列，在不同窗口、不同市场状态下既可能表现为动量延续，也可能表现为过度反应后的反转。它之所以是全库最基础的构件，不是因为它自带 alpha，而是因为它是「收益」这个概念的最小充分统计量：几乎所有相关性检验、分位条件、regime 对比、因子归因都需要一个右侧收益载体。把它单独抽出成 pattern，是为了让每个下游逻辑都能显式声明自己用的是哪一种收益口径。

**为什么要做 signed-log**：原始简单收益的分布是右偏的（跌幅受跌停约束而有界，涨幅 / 暴涨尾部很长）。signed-log 保号且把大偏离压缩，使截面分布更接近对称、极值不主导排序。代价是变换后的数值不再等于真实收益，**只能作排序 / 比较，不能用于精确损益计算**。

**与相邻字段的区别**：

- [[patterns/fields/收盘收益|收盘收益]]：公式与语义完全相同，是同一构件的另一命名，二者不可当作两个独立特征同时入模；
- [[patterns/fields/绝对收益|绝对收益]] / [[patterns/fields/绝对收盘收益|绝对收盘收益]]：去掉方向、只保留幅度，服务于波动 / 冲击 / 非流动性类分子；
- [[patterns/fields/超额收益|超额收益]]：收益率再减去截面中位数，剥掉市场共同方向、只留个股相对强弱。

## 加工公式

```
r = close_t / close_{t-1} - 1        # 仅当两期价格均 > 0，否则 null
signed_log(r) = sign(r) * ln(1 + |r|)
```

## 适用场景

- 作为**通用右侧收益**：相关性、分位分组、regime 划分、因子评价的基准输入；
- 作为**动量 / 反转信号本体**：配合不同 lag 与聚合窗口，构成动量或反转因子的原始序列；
- 需要**压缩极端值**时优先用 signed-log 口径（如极端行情样本多、排序易被暴涨暴跌主导）；
- 需要**精确收益数值**（损益、换手成本测算）时改用原始简单或对数收益。

## 可变异维度

- lag：1 → 2/5/20
- transform：signed-log → 原始收益

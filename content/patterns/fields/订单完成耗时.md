## 金融解释

**衡量什么**：把「订单最早挂出时间」与「订单平均完结时间」取对数后再相减，得到订单从挂出到完结的平均存活时长的对数增量：$\text{order\_completion\_time} = \text{sgn}(d)\cdot\ln(1+|d|)$，其中 $d = \ln(\text{AvgLastTime}+1) - \ln(\text{AvgFirstTime}+1)$。它综合了买卖两侧，是**全市场挂单耐心程度**的总体度量。

**为什么有信息量**：订单存活时长是流动性提供者**耐心**的直接体现。愿意长时间挂单等待成交的参与者，实际上是在提供即时流动性、承担库存与逆向选择风险；反之，订单被迅速成交 / 撤走，说明交易节奏急、耐心低。因此完成耗时越长，通常对应流动性供给意愿越强、市场微观结构越「厚」；越短则对应交易急躁、流动性需求主导。它与订单是否最终成交、是否被主动单吃掉共同刻画了市场的执行效率。

**与相邻字段的区别**：

- [[patterns/fields/买方完成耗时|买方完成耗时]] / [[patterns/fields/卖方完成耗时|卖方完成耗时]]：本字段的**分方向版本**，只在买侧或卖侧统计。全订单版本衡量总体耐心，分方向版本可揭示买卖两侧耐心差异（例如买侧耐心远高于卖侧，可能预示需求更持久）。
- [[patterns/fields/成交执行率|成交执行率]]：度量「实际成交 / 挂单总量」，是**成交比例**；完成耗时度量「挂了多久才结清」，是**时间维度**的执行效率，二者互补。
- [[patterns/fields/成交笔数压力|成交笔数压力]]：从笔数失衡看压力方向；完成耗时不带方向，只描述存活时长。
- 撤单类字段：撤单是「未完结」的另一种结局；完成耗时与撤单率共同刻画挂单的命运结构。

## 收益来源

本页归属 [[alpha/非流动性与冲击补偿|非流动性与冲击补偿]] [[alpha/信息风险补偿|信息风险补偿]]

**赚什么钱**：其一为**流动性溢价**——挂单存活时间长的参与者是在提供即时流动性、承担被动成交风险，理应获得补偿；完成耗时是流动性供给耐心的代理，耐心越强、供给越稳，对应的流动性补偿越有支撑。其二为**信息不对称**——知情者希望快速完成、不愿挂单等待暴露意图，因此低完成耗时（急躁、快速结清）可能标记知情交易，而高完成耗时则更多是被动流动性提供者。

**对手方**：需要即时成交、以主动单吃掉耐心挂单的急躁交易者；以及为流动性提供者的库存风险买单的一方。

**理论支撑**：[[concepts/信息不对称与PIN|信息不对称与PIN]]。

**失效条件**：

- **高撤单率环境**：订单整体存活时间被频繁撤单压缩，完成耗时更多反映撤单策略而非流动性耐心；
- **算法拆单与冰山单**：可见订单的存活时间被算法重塑，与实际流动性供给意愿脱钩；
- **行情剧烈期**：价格快速变动使所有订单几乎瞬间成交或被撤，完成耗时的截面上差异被压缩。

## 加工公式

```
d = ln(AvgLastTime + 1) - ln(AvgFirstTime + 1)      # 对数时间差
order_completion_time = sign(d) * ln(1 + |d|)        # signed-log 变换
# 时间戳缺失或为 0 时置 null
```

## 适用场景

- 作为**挂单耐心 / 流动性供给意愿**的总体度量，用于流动性状态因子或执行质量评估；
- 与分方向版本配合，研究买卖两侧耐心差异与后续价格方向的关系；
- 与 [[patterns/fields/成交执行率|成交执行率]] 组合：高执行率 + 长耗时 = 稳健的流动性供给，低执行率 + 短耗时 = 高频撤单；
- 在**订单级别数据完整**（含挂出与完结时间戳）的市场中可用；只有成交记录、无挂单生命周期的数据无法构造。

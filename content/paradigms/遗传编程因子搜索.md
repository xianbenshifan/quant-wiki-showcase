## 范式概述

遗传编程（Genetic Programming）因子搜索范式：以既有的 ops/mask/agg 算子树库为**原语**，通过进化算法（选择 / 交叉 / 变异）组合出因子表达式树，并按回测 / 相关性等**适应度**搜索最优构造。

**这是一条元范式（meta-paradigm），不是一条具体因子构造**：前面所有范式页都在描述「一个特定的因子怎么算、为什么能赚钱」；而本页描述的是「如何**自动搜索**出尚未被人类写出的因子」。因此它的 `pipeline` 标记为 `unclassified`——它不对应某一条固定的五段流水线，而是**用五段中的各段算子作为积木**去穷举组合空间。这也是它没有 `return_source` 的原因：赚什么钱取决于搜索出来的那个表达式，无法先验指定（见 §关于收益来源）。

**为什么需要它**：人工构造因子受限于研究者的想象力与时间，而算子树库（60 个 ops、14 个 mask、22 个 agg）的组合空间是指数级的。GP 把「找因子」从「手工设计」转为「**带约束的搜索**」——用强类型约束保证生成的树是合法算子组合，用适应度函数（IC / 回测 / 与已有因子的相关性）引导搜索方向。本页记录的是这套**方法论**，因此它更接近「研究基础设施」而非「一个 alpha」。

**与 mode_based 实现的关系**：算子全集复用已实现的数值算子（`ops` / `mask` / `agg`，即五段流水线中的三段），GP 层本身只负责类型签名、参数网格与搜索调度——**不重复实现任何数值逻辑**。这种分层使「算子库升级」与「搜索策略改进」可以独立演进。

## 构造要点

① **原语集**：`field_float / bool / cat`（叶子）+ `ops`（log / pct / cs_rank / ts_diff / …）+ `mask`（gt / quantile_ge / …）+ `agg`（agg_mean / agg_std / …）。
叶子节点对应数据字段（见 [[data-semantics/量价/价格#收盘价|收盘价]] 等语义页），非叶节点对应各类算子——每类原语与知识库中对应的 pattern 类别一一对应（`ops`→[[patterns/ops/截面算子/截面排名|截面排名]] 等；`mask`→[[patterns/mask/分位掩码|分位掩码]] 等；`agg`→[[patterns/agg/均值聚合|均值聚合]] 等）。

② **强类型约束**：每个算子的输入 / 输出类型（`float` / `bool` / `cat`）约束树合法性。
这一步是**搜索效率的关键**：无类型约束时绝大多数随机生成的树在语义上非法（如对布尔量求均值、对类别量做回归），评估成本被浪费。类型系统把搜索限制在「有意义的组合」内，这是 GP 在因子搜索上可行的前提。

③ **参数网格**：如窗口 `[24,120]`、分位 `[0.2,0.4]`、lag `[1,2,3]`、`n_bins [4,8]`。
参数不作为搜索树的节点，而是以网格形式外挂——这样同一棵树的不同参数化可被分别评估，避免参数搜索与结构搜索互相干扰（也控制搜索空间规模）。

④ **进化流程**：种群初始化 → 适应度评估（含计算成本 LPT 调度） → MAP-Elites 归档 / 选择 → 交叉变异 → 迭代。
- **MAP-Elites 归档**：按多个维度（如「低相关 × 高 IC」）维护精英网格，保留**多样性**而非只留最优——避免搜索过早收敛到单一种类的因子；
- **LPT 调度**：把评估任务按计算量从大到小分配到并行单元，缩短整体评估时间——因子回测成本差异很大，调度优劣直接影响可搜索的代数。

⑤ **符号回归路线的具体算子与变异**（gplearn 系，本页第二实例）：把经典遗传算法改造为适应个股面板数据——**个体选择用锦标赛**（`tournament_size` 越大收敛越快、越小多样性越高）；迭代到设定**代数**即终止；变异含**交叉**、**子树变异**、**Hoist 变异**（把子树提升取代原节点、与公式树膨胀对抗、简化结构）与**点变异**（替换节点/常量，重新引入被淘汰的函数与变量）；用**节俭系数（parsimony coefficient）**控制膨胀（取值通常很小如 0.001，需在预训练中调参，过大则树缩成单变量、过小则严重膨胀）；树复杂度以**深度与节点数**衡量，训练前需**预训练**确定超参数组合。适应度可用改造后的 **IC**（见 §实例）。

## 数据语义与流水线

本页为元范式，`pipeline: unclassified`（不使用固定五段）。它不描述某条具体构造，而是以五段中的算子为原语进行组合搜索：

- 叶子字段 ← `data-semantics` 页登记的语义
- 内部节点 ← `patterns/{ops, mask, agg, fields}` 各类算子页
- 搜索产物 = 一棵类型合法的表达式树，展开后即为一条具体范式（其 `pipeline` 五段由树结构决定）

## 实例（同机制不同实现）

**实例 A · 强类型算子库 + MAP-Elites**（原 `mode_based`/`gp` 实现）：见上「构造要点」①②③④。

**实例 B · gplearn 符号回归 + IC 适应度 + ICIR 合成**（江海证券，2024；遗传算法因子挖掘与合成）：

- **原语集**：`function_set` 含基本数学运算与**时间序列运算**；常量范围 `const_range=(-1,1)`；叶子为 96 个特征（10 个行情变量 + 86 个量价类变量，如收盘价、最高价、最低价、成交量、成交额及情绪/技术/动量类）。
- **超参**（研报给出 17 项，代表值）：`generations=5`、`population_size=1000`、`tournament_size=50`、`init_depth=(2,10)`、`init_method='half and half'`、`hall_of_fame=100`、`n_components=20`、`p_crossover=0.4`、`p_subtree/p_hoist/p_point_mutation=0.01`、`p_point_replace=0.04`、`parsimony_coefficient=0.001`、`max_samples=0.1`、`n_jobs=-1`。
- **适应度**：改造后的 **IC（Pearson IC）** —— 以 $t$ 时刻因子值为 $X$、以 $t+1$ 收盘价计的收益率为 $Y$，度量截面预测力。
- **样本**：中证全指剔除 ST/\*ST；训练 2016–2019、测试 2020；经 5 轮终止后按 IC 排序取 **15 个因子**（表达式含大量非线性运算，底层用到 BBIC(biased Bollinger indicator? 见 BBI动量) / EMA5 / Rank1M / MASS / VOL10 / CCI20）。输出具随机性：换随机种子 / 超参 / 输入会得到不同因子。
- **合成**：对 15 个因子先截面标准化 + Winsorize 缩尾，再用 [[patterns/agg/ICIR加权聚合|ICIR加权聚合]]（最大化 IC_IR 加权）合成；协方差用**收缩**修正（见 [[concepts/协方差收缩|协方差收缩]]）。
- **绩效**（2018-01 至 2024-08，中证全指，不计成本）：组 1 年化 27.3%、夏普 1.05、最大回撤由基准 39.3% 降至 28.4%、IC 0.06、IR 1.45。

> 两实例的差异正在于本页「可变异维度」各轴：原语集（强类型 ops/mask/agg ↔ 数学+时序函数）、参数网格（外挂网格 ↔ `const_range`/`function_set`）、搜索目标（多目标回测 ↔ IC）、归档方式（MAP-Elites ↔ `hall_of_fame`+`n_components`）。

## 可变异维度

- 原语集：`ops` / `mask` / `agg` 任意子集；或数学 + 时间序列函数集（缩小可提升效率、牺牲表达力）
- 参数网格：窗口 / 分位 / 滞后 / 分桶的取值集合；或常量范围 `const_range`
- 搜索目标：适应度函数（IC / 回测收益 / 与已有因子相关性 / 多目标加权）
- 归档维度：MAP-Elites 的网格轴（相关性 × IC × 换手等）；或 `hall_of_fame` + `n_components`
- 类型系统：严格 `float/bool/cat` ↔ 放宽类型转换
- 抗膨胀：Hoist 变异概率 / 节俭系数 / 最大深度 / 剪枝
- 产物收口：搜索出的多条因子如何合成（等权 / IC 加权 / [[patterns/agg/ICIR加权聚合|ICIR加权聚合]]）

## 关于收益来源（元范式）

**本页不标注 `return_source`**：该字段回答「这个构造赚什么钱」，而元范式的收益来源**由搜索出的表达式决定**——同一次 GP 搜索可能产出反转类、动量类、流动性类等完全不同性质的因子，无法先验指定一个枚举值。

判定搜索产物的收益来源，应回到**产物自身**：搜索得到的每条表达式在展开为具体范式页（或 reproduce 脚本）时，按该因子的实际构造标注其 `return_source`。因此本页在收益来源的计数与统计中**豁免**（见 `validate_kb.py` 对 `pipeline: unclassified` 的处理）。
